```
HOD registers normally → Individual account
         ↓

         ↓
Fills: Department name, hospital name
Sets: Shift times (Morning/Evening/Night)
Sets: Max concurrent (default 2C + 6R)
Sets: Overflow allowed (default yes)
         ↓
POST /api/department/create
Creates: departments row
Creates: 3 default shifts
HOD user gets: role = "hod" in department_members
         ↓
Department created → goes to Manage Roster screen
         ↓
HOD adds doctors by email:
POST /api/department/:id/invite
{ email, role: "consultant"|"resident" }
         ↓
Backend checks:
  Does user exist with this email?
    YES → add to department_members (status: pending_accept)
          send push notification + email
    NO  → create department_invites row
          send invite email with token link
         ↓
HOD sees roster with statuses:
  ✓ Active  ⏳ Invited  ✗ Inactive
```

## Flow 5 — Shift Handover (end of shift)

```
15 min before shift end:
  Backend cron (or client-side timer) fires
  Push notification → all active doctors in shift:
  "Your shift ends in 15 minutes.
   Complete handovers and log out."
         ↓
Doctor goes to Cases screen
Each active case shows: [Hand Over] button
         ↓
Doctor taps [Hand Over] on a case:
  Modal opens:
  - Select shift to hand over to
  - Add bed number (text input)
  - Add pending notes (multiline)
  Taps [Confirm Handover]
  POST /api/cases/:id/handover
  { toShiftId, bedNumber, pendingNotes }
  case_handovers row created
  Case flagged: status = "handed_over"
  Outgoing doctor access → READ ONLY
         ↓
After handing over all cases:
  Doctor taps [End Shift & Log Out]
  POST /api/shifts/:sessionId/checkout
  shift_sessions → checkedOutAt = now, status = "completed"
  Slot freed immediately
         ↓
CRITICAL CHECK:
  If doctor tries to leave shift WITHOUT handing over:
  "You have X cases not yet handed over.
   Hand them over or mark them complete before logging out."
  Cannot force-exit shift with active non-handed cases

─────────────────────────────────────────

INCOMING SHIFT — receiving handover:
  Doctor checks in to their shift
  Cases screen shows: "RECEIVED — X cases waiting"
  Each case card shows:
    Patient name, complaint, priority
    "From Dr. [Name] · [Time]"
    Pending notes preview
  Taps [Take Over]
  POST /api/cases/:id/handover/receive
  case_handovers → receivedByUserId, receivedAt
  Case moves to their active queue
  Full case sheet accessible — read + write
```

## Critical Edge Cases — Handle These

```
1. Doctor in two departments:
   → Allow — they choose which department at shift select
   → Each department tracked separately

2. Doctor's individual plan + department plan:
   → Department plan features take precedence during shift
   → Individual plan active when not in a shift

3. HOD removes doctor mid-shift:
   → Doctor finishes current shift
   → Cannot check into next shift after removal
   → HOD can force-logout immediately if needed

4. Shift time overlap (e.g. doctor forgets to log out):
   → 15 min warning sent
   → After shift end + 30 min grace:
     System auto-checks out (soft logout)
     Cases not handed over get flagged: NEEDS HANDOVER
     HOD alerted

5. No consultant on shift (both slots empty):
   → Residents can still work normally
   → Escalation goes to HOD notification instead
   → HOD dashboard shows: "No consultant on duty"

6. Internet drops during handover:
   → Handover data saved locally first
   → Synced to backend when connection restored
   → Case not marked handed-over until backend confirms

7. Doctor tries to check in to wrong shift:
   → "Evening shift is not active yet.
      It starts at 14:00. Current time: 12:30."
   → They can still check into the current shift

8. Payment fails after team is active:
   → 7-day grace period
   → Doctors can still work during grace
   → After 7 days → reverts to individual plans
   → Cases and data fully preserved
```
