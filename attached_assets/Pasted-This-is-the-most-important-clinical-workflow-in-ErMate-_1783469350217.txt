```

  Multiple doctors documenting
  3-4 shift handovers
  Lab reports coming in waves
  ECG, Echo, CT results
```

## The Three Things That Must Work

---

### Thing 1 — Addendum Logic

```
Every new dictation or typed update
on an existing case creates a NEW
TIMESTAMPED ADDENDUM — not a new
case note.

The original case note is LOCKED
after creation. It never changes.
(Medico-legal requirement)

Corrections go into addenda:
"Corrected — patient's age is 54 not 52"
→ ADDENDUM 04-07-2026 · 15:00
  CORRECTION: Patient age corrected
  to 54 years.

Results go into addenda:
"Troponin 0.8 raised"
→ ADDENDUM 04-07-2026 · 16:45
  Investigation result received:
  Troponin T: 0.8 ng/mL (elevated)

Consultant reviews go into addenda:
"Cardiology reviewed — Echo shows 40% EF"
→ ADDENDUM tagged as CONSULTANT REVIEW
  With consultant name and time

Cross-consultations go into addenda:
"Nephrology consulted — AKI stage 1"
→ ADDENDUM tagged as CROSS-CONSULTATION
  With specialty and consultant name
```

## What to Build — Tell Your Developer

**Database change — addendum types:**

```typescript
// Every addendum must have a type:
type AddendumType =
  | "clinical_update"      // doctor adds findings
  | "investigation_result" // lab/imaging result
  | "consultant_review"    // senior reviews case
  | "cross_consultation"   // another specialty consulted
  | "medication_change"    // drug added/changed/stopped
  | "procedure_note"       // procedure performed
  | "shift_handover"       // shift change entry
  | "correction"           // corrects earlier entry

// addenda table:
{
  id, caseId, type,
  content, // structured JSON
  doctorId, doctorName, doctorRole,
  specialty, // for cross-consultations
  timestamp,
  shiftId,
  handoverFromDoctor, // for handovers
  handoverToDoctor,   // for handovers
}
```

```
Generate a comprehensive "Course in Hospital"

Use ALL of the following data:

  All investigation results: ${results}
  All consultations: ${consultations}
  All handovers: ${handovers}
  All procedures: ${procedures}
  Discharge vitals: ${dischargeVitals}

Structure the narrative as:
  1. Brief presentation paragraph
  2. INITIAL ASSESSMENT section
  3. INVESTIGATIONS section (all results)
  4. CONSULTATIONS section (each specialty)
  5. INTERVENTIONS section (procedures done)
  6. CLINICAL COURSE section (what happened over time)
  7. CONDITION AT DISCHARGE section

Write as a proper medical narrative —
not bullet points, not "not documented".
Include timestamps for key events.
Include all consultant names and specialties.
Include the total ER stay duration.

This must be comprehensive enough that
any doctor picking up the patient from
the discharge summary knows the full story.
```

## Summary — Three Rules

```
RULE 1: INITIAL CASE NOTE IS LOCKED
  Created once by the first doctor
  Never edited
  All changes go into addenda

RULE 2: EVERYTHING IS TIMESTAMPED
  Every addendum: date + time + doctor
  Every handover: who gave, who received
  Every result: when it arrived
  Every consultation: when done, by whom

RULE 3: DISCHARGE SUMMARY READS EVERYTHING
  Course in Hospital pulls from:
    Initial note
    All addenda
    All results
    All consultations
    All handovers
    All procedures
  Assembled chronologically
  Written as a clinical narrative
  Complete enough to stand alone
```

This is the backbone of ErMate for complex ER stays. Build this correctly and ErMate becomes genuinely indispensable — not just for quick cases but for every patient who stays in the ER more than a few hours.
