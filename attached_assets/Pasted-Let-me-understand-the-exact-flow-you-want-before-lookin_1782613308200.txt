**Backend changes:**

```
1. Add invite_token to departments table:
   invite_token TEXT UNIQUE
   Generate on department creation:
   invite_token = crypto.randomBytes(16).toString('hex')

2. New route — GET /api/department/join/:token

   Used by join screen to show department info

3. New route — POST /api/department/join/:token
   Body: { name, role, googleUserId, email }
   Creates department_members row with status: "pending"
   Sends push notification to HOD

4. New route — GET /api/department/:id/pending
   Returns all pending member requests (HOD only)

5. New route — POST /api/department/members/:memberId/approve
   Updates status → "active"
   Sends push notification to the approved doctor

6. New route — POST /api/department/members/:memberId/decline
   Updates status → "declined"

7. Regenerate invite link:
   POST /api/department/:id/regenerate-invite
   Creates new token (old link stops working)
```

## Why the Current Flow Was Broken

The old flow required HOD to type each doctor's email manually. That's not how Indian ER teams communicate — they use WhatsApp groups. A shareable link is the right model.

This new flow:
- HOD creates department → gets one link
- Shares to WhatsApp group — all 36 doctors get it
- Each doctor clicks, signs in with Google, fills name and role
- HOD approves each from one screen
- Subscription activates for the whole team

Much simpler. Much more likely to actually get used.
