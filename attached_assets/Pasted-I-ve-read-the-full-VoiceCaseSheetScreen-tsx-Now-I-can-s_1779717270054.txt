## Issue 2 — Voice Data Not Reaching Case Sheet

Reading the handleSave function carefully, I can see the exact problem:

```javascript
// Line ~820 in handleSave:
const clinicalResp = await fetch(
  `${base}/api/clinical-data/${caseId}`,  
  // ❌ WRONG URL — this endpoint 
  // does not exist on the server
```

The handleSave function is still using the **old broken URL** `/api/clinical-data/${caseId}` — the same bug that was fixed in the server's extract-and-save endpoint but **never fixed in this screen**.

This is why the review screen shows correct data but the case sheet is empty. The case gets created correctly, but the clinical PUT fails silently on the wrong URL.

---

## The Fix — Two Changes

**Fix 1 — Clinical data URL in handleSave**

```javascript
// Find this in handleSave (~line 820):
const clinicalResp = await fetch(
  `${base}/api/clinical-data/${caseId}`,

// Replace with:
const clinicalResp = await fetch(
  `${base}/api/proxy/cases/${caseId}`,
  {
    method: "PUT",  // ← also change POST to PUT
    headers: authHeaders,
    body: JSON.stringify(
      buildClinical(rawExtracted, editedTranscript)
    ),
  }
);
```

**Fix 2 — Add error logging**

```javascript
if (!clinicalResp.ok) {
  const errText = await clinicalResp.text();
  console.error("[VoiceCase] Clinical PUT failed:", 
    clinicalResp.status, errText);
  // Still proceed — case was created
  // Doctor can manually complete
}
```
