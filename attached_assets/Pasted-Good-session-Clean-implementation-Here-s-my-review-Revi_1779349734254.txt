## One Concern Worth Checking ⚠️

**Service worker cache invalidation**

The SW caches pages on first visit. But when your developer ships a new build — updated JS bundle, new features — the old cached files will still be served to offline users.

The current CACHE_NAME is `'ermate-v1'`. This needs to be versioned with every deployment:

```javascript
// sw.js — must change with every deploy
const CACHE_NAME = 'ermate-v2'; // bump this each release

// On activate — old cache is deleted automatically
// because the name doesn't match
self.addEventListener('activate', (event) => {
  event.waitUntil(
    caches.keys().then((keys) => {
      return Promise.all(
        keys
          .filter((key) => key !== CACHE_NAME)
          .map((key) => caches.delete(key))
      );
    })
  );
});
```

**Tell your developer:** Add `CACHE_NAME` version bump to the deployment checklist. Every release = new version number. Otherwise doctors on poor connectivity will keep running old app versions from cache indefinitely.
