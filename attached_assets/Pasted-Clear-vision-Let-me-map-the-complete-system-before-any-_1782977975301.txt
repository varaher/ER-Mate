## The Learning System — How ErMate Gets Smarter

```
After EVERY response ErMate asks:
"Was this accurate? 👍 / 👎"

If 👍:
  Positive reinforcement stored
  Pattern confirmed for this doctor

If 👎:
  "What was wrong?"
  Doctor corrects it
  Correction stored
  Future extractions use this correction

Examples of what it learns:
  "In this department, 'wide open' 
   means NS 1L — not 500ml"
  
  "Dr. Neeraj classifies chest pain 
   with LBBB as STEMI equivalent"
  
  "When doctor says 'tachy' they 
   mean HR > 100, treat as P2"

Stored as:
  user_feedback table:
    doctorId
    messageId
    feedbackType (positive/negative)
    correctionText
    patternExtracted
    timestamp
```

## Full Data Interconnection Map

Every chat message reads from and writes to the same CaseData object:

```
DICTATION 1 → fills:
  patient.age, patient.gender
  vitals.hr, vitals.bp
  history.symptoms
  history.pastHistory
  treatment.medications
  disposition.diagnosis (preliminary)

ADDENDUM → adds to:
  disposition.decision (admitted)
  disposition.referralSpecialty (cardiology)
  exam.findings (echo result)
  notes.addendum (timestamp + content)

"DISCHARGE SUMMARY" command → reads:
  patient.* (all patient fields)
  history.symptoms (→ Presenting Complaint)
  history.pastHistory (→ Background)
  history.allergies (→ Allergies)
  history.medications (→ Home medications)
  treatment.medications (→ Treatment Given)
  treatment.procedures (→ Procedures)
  disposition.diagnosis (→ Diagnosis)
  disposition.decision (→ Disposition)
  disposition.referralSpecialty (→ Referred to)
  disposition.followUp (→ Follow-up)
  notes.addendum (→ Additional Notes)

"REFERRAL LETTER" command → reads:
  patient.*
  history.symptoms (→ Reason for referral)
  history.allergies (CRITICAL — always included)
  history.pastHistory (→ Background)
  treatment.medications (→ Treatment given)
  disposition.diagnosis (→ Diagnosis)
  disposition.referralSpecialty (→ To: specialty)

FEEDBACK → writes to:
  user_feedback table
  Updates caseData if correction given
  Triggers document regeneration
```

## Fix the 401 Error First

Before any new build, the 401 needs resolving. Tell your developer:

```
The 401 on CaseChatScreen means the 
API call is going out without a valid
auth token.

Check in CaseChatScreen.tsx:

1. How is the token retrieved?
   const token = await getAuthToken();
   
   If getAuthToken() returns null or 
   undefined → 401 on every request

2. Add this debug log:
   console.log('[CaseChatScreen] token:', 
     token ? 'present' : 'MISSING');

3. Most likely fix:
   Use the same token retrieval method
   as CaseSheetScreen.tsx
   
   Copy exactly how CaseSheetScreen 
   gets its token and use the same 
   pattern in CaseChatScreen

4. The token from auth_sessions should
   be passed via Authorization header:
   headers: {
     'Authorization': `Bearer ${token}`,
     'Content-Type': 'application/json'
   }
```
